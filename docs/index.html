Widya Auth API

REST API portal autentikasi: buat akun, login, dan akses profile dengan JWT. Knowledge Test Software Engineer - PT Widya Informasi Nusantara.

RingkasanMenjalankanArsitekturEndpointData & keamananAsumsiTestingPengembangan lanjut

1. Ringkasan

Semua orang dapat membuat akun (nama, email, jenis kelamin), login, lalu mengakses profile mereka sendiri dengan header token JWT. Semua response berbentuk JSON.

AspekPilihan
RuntimeNode.js 18+
FrameworkExpress 4
DatabasePostgreSQL (driver pg, query terparameter)
AutentikasiJWT (jsonwebtoken), password di-hash bcrypt (bcryptjs)
DokumentasiHalaman ini + Swagger UI di /docs
TestIntegration test dengan node:test bawaan Node

2. Menjalankan di lokal

npm install
cp .env.example .env     # isi DATABASE_URL dan JWT_SECRET
docker compose up -d     # opsional: PostgreSQL via Docker
npm run migrate          # membuat tabel users
npm start                # http://localhost:3000
VariabelWajibKeterangan

4. Endpoint

Base URL: http://localhost:3000

POST/api/auth/register Buat akun baru

FieldAturan
namewajib, maks 100 karakter
emailwajib, format valid, unik (disimpan lowercase)
genderwajib: male atau female
passwordwajib, 8-72 karakter
curl -X POST localhost:3000/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"name":"Budi Santoso","email":"budi@example.com","gender":"male","password":"rahasia123"}'

201 Created

{
  "success": true,
  "message": "Akun berhasil dibuat",
  "data": { "id": 1, "name": "Budi Santoso", "email": "budi@example.com",
            "gender": "male", "created_at": "2026-10-30T16:24:37.084Z" }
}

400 Validasi gagal, 409 Email sudah terdaftar. Contoh 400:

{ "success": false, "message": "Validasi gagal",
  "errors": { "email": "email tidak valid", "password": "password 8-72 karakter" } }

POST/api/auth/login Login dan dapatkan JWT

curl -X POST localhost:3000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"budi@example.com","password":"rahasia123"}'

200 OK

{
  "success": true,
  "message": "Login berhasil",
  "data": { "token": "eyJhbGciOi...", "tokenType": "Bearer", "expiresIn": "1h" }
}

401 bila email atau password salah (pesan sengaja sama: Email atau password salah).

GET/api/profile Profile user yang login

curl localhost:3000/api/profile -H 'Authorization: Bearer <token>'

200 OK

{ "success": true,
  "data": { "id": 1, "name": "Budi Santoso", "email": "budi@example.com",
            "gender": "male", "created_at": "2026-10-30T16:24:37.084Z" } }

401 bila header hilang, token tidak valid, atau kedaluwarsa.

Endpoint pendukung: GET /health (health check) dan GET /docs (Swagger UI interaktif).

StatusArti

5. Data dan keamanan

CREATE TABLE users (
  id            SERIAL PRIMARY KEY,
  name          VARCHAR(100) NOT NULL,
  email         VARCHAR(255) NOT NULL UNIQUE,
  gender        VARCHAR(10)  NOT NULL CHECK (gender IN ('male','female')),
  password_hash VARCHAR(100) NOT NULL,
  created_at    TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);
  • Password di-hash bcrypt dan tidak pernah muncul di response.
  • Semua query memakai parameter ($1, $2) sehingga aman dari SQL injection.
  • Duplikat email ditangkap dari unique constraint (kode 23505), bukan cek-lalu-insert, jadi bebas race condition.
  • JWT berisi sub (id user), ditandatangani JWT_SECRET, kedaluwarsa sesuai JWT_EXPIRES_IN.
  • Pesan error login sama untuk email dan password salah agar akun tidak bisa ditebak.
  • Ukuran body dibatasi 10 KB. .env tidak pernah di-commit.

6. Asumsi desain

Soal hanya menyebut nama, email, dan jenis kelamin. Karena login butuh kredensial, saya menambahkan password.
  • Login memakai email dan password.
  • Gender dibatasi male dan female, dijaga di validasi dan di database.
  • Profile hanya bisa dilihat oleh pemilik token (tidak ada parameter id, sehingga tidak ada akses silang antar user).
  • Skema dibuat lewat satu skrip migrasi idempoten (CREATE TABLE IF NOT EXISTS) agar setup cukup satu perintah.

7. Testing

npm run migrate
npm test

Test berjalan end-to-end terhadap PostgreSQL asli dan membersihkan datanya sendiri. Skenario yang dicakup:

  • register, login, lalu profile (alur utama), dan password tidak bocor
  • email duplikat menghasilkan 409
  • validasi input menghasilkan 400 dengan detail per field
  • password salah menghasilkan 401
  • profile tanpa token atau dengan token palsu menghasilkan 401
